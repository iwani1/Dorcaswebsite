Before you start You need: GreenGeeks login · the three ZIPs (luxrio-1.0.1-patched.zip, luxrio-child-1.0.0.zip, luxrio-core-1.0.1.zip) · your domain's registrar login · ~2–3 hours, plus waiting for DNS and SSL.
There is no usable temporary domain on GreenGeeks shared hosting The ~username URL is Managed VPS only. cPanel's random "temporary domain" has no SSL and shows every visitor a "technical domain, not for live use" banner. GreenGeeks has no staging feature. So you will use the real domain, a $10 throwaway domain, or a subdomain you already own — all three give you a clean https:// address. Pick one now, because it changes step 1 only; everything else is identical.

STEP 1 Get the domain pointing at GreenGeeks cPanel → Domains

Do this first — DNS takes the longest, and everything else waits on it.

If you're using the real domain (recommended):

  1. Registrar → set nameservers to ns1.greengeeks.net, ns2.greengeeks.net, ns3.greengeeks.net.
  2. GreenGeeks → Hosting → Manage → cPanel → Domains → Create A New Domain → enter the domain → uncheck "Share document root" → note the folder it suggests (usually public_html/yourdomain.com).
  3. Wait. 15 minutes to 4 hours is normal. Check at whatsmydns.net.

If you bought a throwaway / are using a subdomain:

  1. Buy or create it (review.yourdomain.com works if that domain is already on this account).
  2. cPanel → Domains → Create A New Domain → same as above, uncheck "Share document root". Each domain needs its own document root so it gets its own SSL certificate.
Don't skip the check A 404 means the domain isn't attached to that document root. Fix it now — installing WordPress into the wrong folder is a rebuild, not a repair.

STEP 2 Turn on SSL cPanel → SSL/TLS Status

Before WordPress. If you install over http://, those URLs get written into the database and you inherit mixed-content warnings later.

  1. cPanel → Security → SSL/TLS Status.
  2. Tick the domain → Run AutoSSL.
  3. Wait 5–20 min, refresh until the domain shows a valid certificate.
  4. cPanel → Domains → switch on Force HTTPS Redirect for the domain.
AutoSSL keeps failing? That's DNS. It will keep failing until propagation finishes — that's the intended behaviour, not a bug to work around. Don't install WordPress on plain HTTP in the meantime.

STEP 3 Set PHP 8.3 and raise the limits cPanel → Select PHP Version

This step decides whether the demo import succeeds or 504s halfway through.

  1. cPanel → Software → Select PHP Version → choose 8.3.
  2. Click Reset to default on extensions, then confirm these are ticked: mbstring, pdo_mysql, curl, gd, intl, zip, exif, fileinfo.
  3. Switch to PHP Options and set the values below.

max_input_vars5000critical at the default 1000 the theme's options panel silently truncates saves — no error, your settings just don't stick

STEP 4 Install WordPress cPanel → Softaculous → WordPress

  1. cPanel → Software → Softaculous Installer → WordPress → Install.
  2. Protocol: https://  ·  Domain: your domain, without www  ·  Directory: leave blank.
  3. Site Name: Dorcas.
  4. Admin Username: not admin — e.g. dorcas_admin.
  5. Admin Password: generate strong, save it in your password manager now.
  6. Admin Email: an inbox you read — order notifications land here during testing.
  7. Under Advanced Options: Auto Upgrade → "Do not auto upgrade", and tick Disable Search Engine Visibility.
  8. Install, then log in at https://yourdomain/wp-admin.

STEP 5 Baseline settings WP Admin → Settings

  1. Settings → General — Timezone Africa/Accra.
  2. Settings → Permalinks — Post name. must Without this, product URLs and the theme's links break.
  3. Settings → Reading — "Discourage search engines" stays ticked for now.
  4. Users — delete other admins.
  5. GreenGeeks dashboard — turn plugin/theme auto-updates off for this site. An Elementor or WooCommerce major landing unannounced will break the header builder, and you'll be debugging it in front of the client.
  6. Plugins — delete Hello Dolly and Akismet.
  7. Themes — keep one Twenty* theme as an escape hatch; delete the rest later.

STEP 6 Install the theme Appearance → Themes → Add New

  1. Upload Theme → luxrio-1.0.1-patched.zip → Install Now. Don't activate yet.
  2. Upload Theme → luxrio-child-1.0.0.zip → Install.
  3. Activate "Luxrio Child" — always the child, never the parent, so your changes survive updates.
  4. Plugins → Add New → Upload Plugin → luxrio-core-1.0.1.zip → Install → Activate.
If the uploader times out or says "The link you followed has expired" cPanel → File Manager → public_html/wp-content/themes/ → Upload both theme ZIPs → right-click each → Extract → delete the ZIPs afterwards (they're publicly downloadable otherwise). Then do the same for the plugin in wp-content/plugins/. Finally confirm folders are 755 and files 644 — wrong permissions cause a white screen or a site with no styling, and it looks like a broken theme rather than a permissions problem.
"The theme is missing the style.css stylesheet" means you uploaded the complete package instead of the theme ZIP. Use luxrio-1.0.1-patched.zip, which has a single luxrio/ folder at its root.

Then three more that this host needs:

Never run two page caches No W3 Total Cache, no WP Rocket alongside LiteSpeed Cache. Two caches on one site is how customers end up seeing last session's cart.

STEP 8 Theme options — before importing WP Admin → Theme Options

Set these first so the import inherits them rather than fighting them.

  1. Theme Options → Logo — upload the real logo and real white logo. The bundled SVGs are placeholders I generated for the build; on a live site they'll look wrong.
  2. Theme Options → General — primary colour (default #ff3e01) and fonts. This also drives Elementor's global colours.
  3. Appearance → Menus — create a menu named exactly Primary Menu, assign to Primary Menu and Mobile Menu. The importer looks for that exact name.
  4. Settings → Reading — leave as "latest posts"; the import sets the homepage.

STEP 9 Import the demo content Appearance → Import Demo Data

470 items, 226 images pulled from the vendor's server. Run it once.

  1. Re-check the PHP limits from step 3 are still in place.
  2. Appearance → Import Demo Data → Import.
  3. Leave the tab alone for 3–10 minutes. Don't refresh, don't close.
  4. Wait for "All done".
504 partway through? That's max_execution_time not being applied. Raise it, then retry on a fresh install — re-running on a half-imported site gives you duplicates you'll then have to delete by hand.

Then check four things:

This is the one place my changes could show. The theme shipped Font Awesome Pro, which can't legally be redistributed, so I swapped it for Free and remapped all 88 icon references. If any icon looks like an empty box or the wrong glyph, tell me the page and I'll fix the mapping — don't just live with it.

STEP 10 Email, before anyone tests checkout WP Mail SMTP

WordPress defaults to PHP mail(), which shared hosting IPs get filtered on. Order confirmations vanish silently and you spend a day chasing a bug that doesn't exist.

  1. cPanel → Email Accounts → create orders@yourdomain.com.
  2. WP Mail SMTP → Settings → Mailer: Other SMTP.
  3. Host mail.yourdomain.com, port 587, encryption TLS, the mailbox credentials.
  4. From Email must be on your own domain, or SPF fails.
  5. Send a test email — confirm it lands in the inbox, not spam.
  6. Confirm SPF, DKIM and DMARC exist for the domain (cPanel → Zone Editor, or ask support).

Don't skip the test order. Everything else is cosmetic. A store that can't complete an order and send the email is the one failure that costs you the client's confidence on launch day. If you only do one thing on this list, do this one.

STEP 15 Strip the demo content before the client sees it

Budget an hour. This is what makes it look like their shop instead of a template — and it's the first thing they'll judge.

STEP 16 Go live only after sign-off

If you built on the real domain: remove the directory password, untick "Discourage search engines" (Settings → Reading), purge LiteSpeed, add analytics, place one real order and refund it.

If you built on a throwaway domain or subdomain:

  1. Back up first — cPanel → Files → Backup, or UpdraftPlus to Google Drive.
  2. Add the real domain in cPanel → Domains pointing at the same document root as the review site.
  3. Tools → Better Search Replace → search staging-domain.com → replace realdomain.com → tick all tables → Run. never do this with plain SQL — it corrupts serialized data and breaks widgets silently.
  4. SSL/TLS Status → Run AutoSSL for the real domain. Remove the old domain once its certificate is live.
  5. Settings → General: both WordPress Address and Site Address show the real domain with https://.
  6. Purge LiteSpeed, clear your browser cache.
  7. Re-enable indexing; check https://realdomain.com/robots.txt allows crawling.
  8. Update payment gateway webhook URL and the SPF/DKIM records for the new domain.
  9. Place one small real order, then refund it.
